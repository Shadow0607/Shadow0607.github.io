專案狀態：規劃中。以下為預計實作的規格，功能尚未宣稱完成；這是軟體模擬與工程展示專案，不連接真實工廠設備，也不是完整 MES。

專案目標

用虛擬產線與設備模擬製造現場，在沒有 PLC、機台或攝影機的條件下，實作生產訂單、工序派工、設備回報、故障恢復與系統監控，並處理真實的工程問題：

  • API 逾時後重送與重複訊息
  • 兩個 Worker 搶同一台設備
  • 資料庫寫入成功但訊息發送失敗（Outbox）

使用情境

建立訂單 ORD-20260921-001（產品 Motor-A、數量 500、Line-01），依序執行三道工序：

加工 · Machine-A→組裝 · Machine-B→檢驗 · Machine-C

Simulator 可控制設備正常完成、延遲、回傳錯誤、暫時離線及恢復上線。

第一版範圍

  • 建立訂單，依固定工序產生 Job，依順序派工
  • 3 台以上虛擬設備，回報 Idle、Running、Error、Offline
  • 保存訂單、Job、執行紀錄、設備狀態歷史、事件及告警
  • RabbitMQ 傳遞派工事件，搭配 Outbox 避免漏送
  • 重送派工命令沿用同一識別碼，防止重複執行
  • Vue Dashboard 以 SignalR 推播即時更新，輪詢作為斷線 fallback
  • Docker Compose 一鍵啟動全部服務
  • 結構化日誌、關聯 ID 與基本 Trace

架構元件

元件職責
Vue 3 + TypeScript訂單、設備、告警與執行歷史的操作及展示
ASP.NET Core Web API驗證輸入、建立訂單、接收設備回報、查詢 API、SignalR 推播
ASP.NET Core Worker消費派工訊息、狀態轉移與逾時檢查、Redis 去重前置檢查
PostgreSQL + EF Core持久資料、唯一約束、交易及 Outbox／Inbox 紀錄
RabbitMQ傳送派工及狀態事件，消費者需容忍重複投遞
Redis去重快取與設備狀態快取（最終保證仍為 DB 唯一約束）
Equipment Simulator模擬設備回應、故障與命令去重
OpenTelemetry串接 API、Worker、Simulator 的 Trace
